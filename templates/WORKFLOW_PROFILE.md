# 工程协作配置

> 此文件是工程开始前开发者与总控共同确认的输入契约，没有自动加载器。
> 未填不代表默认同意；不要填写密码、API key 或访问令牌。

## 状态与来源

- 配置版本：待填写
- 项目上下文路径及版本：待填写
- 状态：草案 / 已确认（当前：草案）
- 开发者确认记录与时间：待填写

## 角色映射

每项填写：模型展示名称、提供方、CLI 模型 ID、effort（开发者指定或由总控决定）、已核验的可用性。

| 角色 | 模型 / 提供方 / CLI ID | effort | 可用性 |
| --- | --- | --- | --- |
| 总控与决策 | 待定 | 待定 | 未核验 |
| 低等级执行者 | 待定 | 待定 | 未核验 |
| 低等级审查者 | 待定 | 待定 | 未核验 |
| 其余等级执行者 | 待定 | 待定 | 未核验 |
| 其余等级审查者 | 待定 | 待定 | 未核验 |
| 最终审核者 | 待定 | 待定 | 未核验 |

总控可选择 Codex Astra / Sol 或已确认可用的 Claude Fable / Opus / Sonnet 等模型。表中没有默认启用任何选择。
同一模型担任多个角色时，说明会话隔离方式和审查独立性局限，由开发者决定。

## 路由与失败处理

- 项目分级标准与任务路由：待填写
- 初次提交后的最大修改次数：3
- 修改耗尽时参与方案讨论的角色：待填写
- 每条任务线的接管者：待填写
- 接管后的独立审查者：待填写
- 接管后仍失败：暂停，通知开发者决定
- 缺少可用接管者或必需能力：暂停相关任务，由开发者决定

## 能力与运行

- 按角色列出的必需 / 可选能力：待填写
- 能力验证方式与证据：待填写
- CLI / 适配器：待填写
- 允许写入范围与并发约束：待填写
- context-mode 是否可用及上下文摘要方式：待填写
- 单次 Codex 上限：25 分钟；切块与续接方式：待填写

## 预算与启动确认

- 模型调用与额度预估及假设：待填写
- 超预算处理：待填写
- 开发者已确认角色、分级、路由、effort、验收、能力、升级和预算：待确认
- 仍未解决的启动阻塞项：待填写

只有开发者实际确认后才能记录“已确认”；模型不得代替开发者批准。
此确认只覆盖所列工程范围，不自动授权外部发布或部署。
