# Contributing

[简体中文](CONTRIBUTING.md) | [Home](README.en.md)

Feedback in Chinese or English is welcome. This project currently contains documentation and scaffolding; distinguish existing behavior from proposed features.

## Feedback and bugs

Use GitHub Issues to explain the problem or use case, expected behavior, and relevant documentation. For bugs, include a minimal reproduction and only necessary, sanitized output. Do not upload private project context, personal email addresses, credentials, or full execution logs.
Discuss substantial design changes in an Issue before implementing them.

## Changes

1. Fork the repository and create a work branch from current main.
2. Keep changes focused and Chinese/English docs and templates semantically aligned.
3. Check links, formatting, and relevant validation. State unrun or unavailable checks.
4. Submit a PR explaining the problem, change, evidence, and related Issue.
5. Address review feedback and wait for the owner's decision.

Load only the language needed for each model task. Maintaining translations does not require loading both copies on every call.

## Merge authority

**Only the repository owner decides whether to merge into main.**
Contributing or opening a PR does not grant write access. Passing reviews/checks is not a promise to merge.
Agents must not push to main, merge PRs, enable auto-merge, or grant write access. The owner performs the final merge in GitHub.
GitHub permissions and branch protection are separate from documentation rules. Recheck merge access when adding collaborators or automations.

## Licensing and third-party content

Contributors must have the right to submit their work and read LICENSE. Retain applicable third-party licenses and sources; do not relicense material without authority.
Commercial development is allowed, but selling the framework or offering it as a paid hosted service is prohibited. See [LICENSE](LICENSE) for full terms.
