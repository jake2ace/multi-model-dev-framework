# 用 Skill 启动项目

[English](skill.en.md) | [返回首页](../README.md)

`multi-model-dev` 把项目启动变成一次对话：你说明想做什么，它协助收集背景、确定分工与预算、生成本地配置，并准备第一个小任务的交接提示词。你不必手动复制和填写整套模板。

**当前是启动 Skill，不是自动调度器。** 执行与独立审查仍需要在已有工具中手动安排；模型调用、计数、25 分钟超时和看板没有自动实现。

## 安装到 Codex

Skill 源码位于 [skills/multi-model-dev](../skills/multi-model-dev/SKILL.md)，包含双语流程、模板和许可证，可以单独复制，不依赖本框架仓库的绝对路径。

在本仓库目录执行（macOS / Linux）：

```sh
skill_root="${CODEX_HOME:-$HOME/.codex}/skills"
mkdir -p "$skill_root"
if [ -e "$skill_root/multi-model-dev" ]; then
  echo 'Skill 已存在；请比较内容后再更新，未覆盖。'
else
  cp -R skills/multi-model-dev "$skill_root/multi-model-dev"
fi
```

打开新的 Codex 会话，在技能列表中查找 `multi-model-dev`，或输入 `$multi-model-dev`。若尚未被发现，重启 Codex 再检查。文件复制成功不等于已验证当前会话加载。
也可以在会话中明确提供已安装的 `SKILL.md` 路径，让 AI 读取它；这是手动读取测试，不是自动发现测试。

复制 Skill 这一步只安装指导文件。使用时它会解释 context-mode 的好处与代价，让你选择安装、跳过或仅检查已有安装；选择安装后由 AI 实际执行安装与验证，需要重启或信任确认时会明确说明。它不会默认安装 Claude、新模型或更改账户权限。其他客户端能否发现、如何安装该 Skill，需按对应客户端验证；本次不宣称完成 Claude Code 兼容性测试。

## 第一次怎么说

在准备开发新项目的目录打开 Codex，发送：

```text
$multi-model-dev
我要开发一个新的项目：<用一句话描述>。
我目前能使用的模型是：<模型列表>。
请用中文，先帮我确定第一版范围、模型分工和预算。
不确定的关键项问我，配置确认后再准备第一个任务。
```

没有项目目录或还没选好技术栈也可以开始讨论，Skill 会在写文件前确认目标路径。不要在本框架的开发会话中默认把新应用建进框架仓库。

它应先复用已给的信息，询问少量关键缺项，再给出能确认的方案。角色不是固定模型，总控也可由你选择。无需为填满配置启用所有提供方。

## context-mode 由你选择

- **可能的好处**：大文件、长日志、批量检索按需取结果，减少原始上下文输入。
- **代价与限制**：增加运行依赖、维护和可能的延迟；本地索引/会话记录占用存储，小任务未必划算；不保证套餐额度节省。
- **你的选项**：安装并验证 / 暂不安装 / 已安装，只检查。拒绝安装不影响基本使用。

选择安装后，Skill 会核验客户端与当前官方方法，检查已有安装、备份相关配置、执行安装注册并验证工具与 hooks。若客户端需要重启或信任操作，会保存待办供新会话续接；不会把“文件已安装”冒充“运行验证通过”。安装流程依赖宿主具备相应工具和权限，不是一个独立的跨平台安装程序。

## 你应该看到什么

1. **启动方案**：第一版目标与验收、模型与 effort、预计调用及停止条件。
2. **两份本地文件**：`PROJECT_CONTEXT.md` 与 `WORKFLOW_PROFILE.md`；未经你确认的配置仍为草案。
3. **下一步**：确认配置并要求试跑后，得到首个任务文件及执行/审查提示词；没有实际执行的步骤标为未执行。

默认建议将记录放在目标项目的 `.multi-model-dev/<project-id>/`，也可使用你指定的目录。Skill 会保留已有内容并检查 Git 忽略；真实背景、记录和凭据不应上传到公开仓库。安装目录只存通用规则，不存你的工程信息。

## 怎么测试这一版

先观察启动体验：

- 已经告诉它的信息，有没有重复问？
- 不懂技术栈时，能不能提出清楚的建议？
- 有没有擅自选模型、把配置写成已确认，或直接开始改应用代码？
- 两份文件的内容是否正确，已有文件是否保留？
- 你是否清楚下一步由谁做、怎么验收、何时停止？

格式校验和安装文件核对只能证明包结构完整；自动发现、真实对话表现以及省额度效果需要实际会话验证。完成首轮任务后，按[试用比较方法](quickstart.md#怎样判断是否更省更快)记录质量、时间和消耗。

## 更新与维护

仓库更新不会自动覆盖本地安装。更新前比较本地改动，再复制选定版本；不要将你的项目配置放进 Skill 包。
维护者修改 `templates/` 时应同步 `skills/multi-model-dev/assets/` 的对应副本；包内 LICENSE 与仓库许可证保持一致。安装 Skill 不改变许可证条款。

参考：[OpenAI Skill 结构](https://developers.openai.com/plugins/build/skills)、[本地 Skill 与评估示例](https://developers.openai.com/blog/eval-skills)。
