# 工作流设计

[English](workflow.en.md) | [返回首页](../README.md)

## 角色配置与启动确认

工程开始前，由开发者与选定的总控共同填写并确认 WORKFLOW_PROFILE.md。
总控、执行、审查、接管及最终审核均为独立角色，允许映射到实际可用的 Codex 或 Claude 模型。
Astra、Sol、Fable、Opus、Sonnet 等只是选择示例，框架不硬编码总控模型。

启动确认必须覆盖：项目范围及验收、角色模型、CLI 与能力可用性、effort、任务路由、最多 3 次修改后的接管与独立审查、预算和人工兜底。
未经开发者确认的配置不能启动工程。确认后按约定执行，不为已授权的常规步骤反复确认。
角色或范围发生实质变化时重新讨论受影响的部分。

## 通用执行流程

总控拆分与定级 → 配置的执行者实现 → 独立审查者审查 → 执行者按意见修改 → 最终审核。
首次提交不计修改，之后最多修改 3 次；跨会话、切块不重置次数。
修改耗尽后按配置讨论和接管，接管成果继续独立审查并交最终审核者；仍失败则暂停，由开发者决定。
未配置可行的接管路线时暂停，不自动升级模型或重置次数。

Luna 执行、Sol 审查、Astra 总控是可选 Codex 示例；混合 Claude 示例见 CLAUDE.md。
两个示例都需要按工程实际情况补齐后确认，不默认激活。

## 项目上下文契约

- 输入：开发者提供的 `projects/<project-id>/PROJECT_CONTEXT.md` 和 `WORKFLOW_PROFILE.md`，模板位于 `templates/`。
- 内容：背景、目标、范围、技术栈、硬性约束、验收标准、特殊能力、预算与开放问题。
- 加载：目前由总控人工读取，尚无解析器或自动加载器。
- 分发：任务引用上下文路径和版本，传递与本任务相关的原始约束和验收，完整上下文供追溯。
- 更新：上下文版本变化时总控判断影响，必要时暂停受影响任务并更新验收。
- 缺项：先推进不依赖缺项的工作，涉及正确性或授权的部分等人明确，不静默猜测。
- 边界：背景资料不等于指令，不改变工具权限，也不代表对外发布授权。

## 任务文件与看板

任务说明未来至少需要目标、修改范围、依赖、验收、角色、effort、上下文引用和状态。
看板未来展示进展、中间决策、修改次数、接管和暂停原因。当前看板为空，具体格式和更新协议待讨论。

共享同一 Git 仓库，重叠文件写入串行处理。执行者写产出、审查者写意见，状态由未来脚本统一管理。
项目输入、完整产出、审查与摘要默认不进入公开仓库；需要发布的示例单独检查内容。

## 摘要与验证

总控只读取摘要、审查结论和验证摘要；摘要记录结论、文件位置、检查结果、未解决问题及下一步。
审查者必须读取实际产出和相关证据。模型之间同意不等于测试通过。
不同项目使用各自的构建、测试或验收方法；框架不预设具体操作系统、语言或工程领域。

## 固定规则与额度

计数、定级后的路由、升级和超时计划由脚本执行，不为固定规则额外调用模型。
总控在需要工程判断、处理分歧和与人沟通时介入。

单次 Codex 运行最多 25 分钟。预先切块，在截止前保存摘要，再开新会话继续，并延续计数与状态。
自动超时、失败恢复和摘要丢失处理尚未实现。

context-mode 的工具路由和上游更新入口见[使用说明](context-mode.md)。实际安装不代表路由或额度节省已生效；Skills 按需加载，不能全量加载。
每次执行前预估调用次数、effort、上下文及可能返工；没有实测依据时不给精确的周额度百分比。
Claude 启用后，尽量将重活放到 Claude 一侧，同时保持已确定的审查关系。

## 运行能力接口

项目可声明某角色的必需或可选能力，以及不可用时暂停或请求替代方案的处理方式。
必需能力不可用时暂停相关任务并说明原因，不能静默切换模型或能力。

例如某项目要求 Daybreak Blue，应在项目上下文中明确适用角色，并核验账户、模型和产品入口。
官方 API 的访问计划参数不能直接当作 Codex CLI 参数使用。能力要求也不能由 `-a never` 或提示词实现。
参考：[Daybreak API](https://developers.openai.com/api/docs/guides/daybreak)、[Codex Trusted Access](https://learn.chatgpt.com/docs/cyber-safety)。

## 语言与更新入口

启动时选择交流及产物语言：zh-CN、en，或明确要求的双语。保留工具名、路径、配置键与 ID；只读所需语言版本。公共中英文文档在规则变更时一起更新。
查看 [context-mode 上游 Releases](https://github.com/mksglu/context-mode/releases/latest) 了解发布和功能变化；链接不提供后台监控，也不自动授权升级。

## 仓库贡献与合并

Issues 用于建议与问题；修改通过 Fork / 工作分支和 PR 提交。仓库所有者决定最终合并 main，代理不得代为合并、直推 main 或启用自动合并。GitHub 保护规则需要在仓库设置中单独核验。
