# multi-model-dev-framework

**简体中文** | [English](README.en.md)

**让多个 AI 分工开发：把额度花在需要判断的地方，用独立审查把住质量。**

你只与一个总控讨论目标；执行者负责完成任务，审查者检查实际成果。模型、effort 和项目要求由你在开始前决定。框架适用于不同类型的工程，不绑定某个模型或项目领域。

**目的：通过多 AI 协作，探索怎样更省额度、更高效地完成开发。** 当前没有完成效果基准测试，不承诺固定节省比例，也不保证多模型一定比单模型快。

> **当前可用：规则、项目模板和手动协作流程。** 自动调度、模型调用、计数、看板更新与超时恢复尚未实现；没有一键启动命令。第一次使用的目标是确认一份协作配置，再手动试跑一个小任务。

## 为什么使用它

| 开发中的问题 | 框架怎么处理 | 希望获得的收益 |
| --- | --- | --- |
| 所有工作都交给高消耗模型 | 按难度分工，单独配置模型和 effort | 把有限额度留给复杂判断 |
| 每个 AI 都反复读全部聊天和日志 | 文件交接、任务相关上下文、总控读摘要 | 减少重复输入 |
| 多个 AI 各做各的 | 一个总控统一目标，执行与审查分开 | 减少沟通混乱，尽早发现问题 |
| 修改循环停不下来 | 首次提交后最多修改 3 次，再按约定接管或交给人 | 控制返工和消耗 |
| 换项目或模型就要重写规则 | 项目背景、角色配置与通用流程分开 | 复用流程，按需调整 |

这些是设计思路，收益需要实测。审查和交接本身也有成本；很小的任务可能用单模型更合适。

## 怎么开始：四步

1. **准备工具**：准备 Git，以及你能使用的 AI 编程工具和模型账户。当前使用不要求安装 Claude，也不要求先安装 context-mode。
2. **准备两份输入**：下载或克隆本仓库，从 `templates/` 复制项目背景与协作配置到本地 `projects/<project-id>/`。不要覆盖目标项目已有的规则文件。
3. **交给总控确认**：告诉它项目目标、可用模型和预算，让它协助补齐两份输入。角色、验收和失败处理由你确认后再开始。
4. **试一个小任务**：手动安排执行与独立审查，保存产出和摘要，核对质量、用时与消耗，再调整下一轮配置。

**直接照做：[首次使用指南](docs/quickstart.md)** — 含复制命令、可粘贴的启动提示词、一个小任务示例和常见卡点。不必先读完所有设计文档。

## 运行时只需重点关注五项

| 关注什么 | 你要能回答的问题 | 去哪里看 |
| --- | --- | --- |
| 目标与验收 | 这次交付什么，怎样才算完成？ | `PROJECT_CONTEXT.md` |
| 模型分工 | 谁总控、谁执行、谁审查，用什么 effort？ | `WORKFLOW_PROFILE.md` |
| 预算与停止条件 | 本轮允许多少调用、多久，何时暂停？ | 协作配置与本轮预估 |
| 质量与返工 | 实际检查通过了吗，已经修改几次？ | `reviews/` 与验证证据 |
| 状态与下一步 | 做到哪里，卡在哪里，需要我决定什么？ | `summaries/`；当前看板尚为空 |

你与总控保持一个沟通入口。详细结果保存在文件中，需要时再追溯；审查者仍须检查真实产出，不能仅凭摘要放行。

## 一次任务怎么流转

```mermaid
flowchart LR
    H[你与总控确认目标和预算] --> E[执行者完成任务]
    E --> R[独立审查者检查成果]
    R -->|需修改：最多 3 次| E
    R -->|通过| F[最终审核]
    R -->|次数耗尽| P[按约定接管或暂停给人]
```

总控、执行者、审查者是**角色**，不是固定模型。Astra 总控、Luna 执行小任务、Sol 审查只是可选例子；总控也可选择 Sol 或已确认可用的 Claude 模型。模型名称与实际 CLI ID、账户可用性须在使用前核验，不能把示例当成已实现的支持矩阵。

完整的接管、最终审核与停止规则见[工作流说明](docs/workflow.md)。

## context-mode 与后续实测

对于长日志和大文件，可选择通过 context-mode MCP 处理并检索所需片段，减少进入模型上下文的原始文本。

- [如何使用 MCP、验证状态和理解统计](docs/context-mode.md)
- [上游最新版本与功能更新](https://github.com/mksglu/context-mode/releases/latest) · [全部更新说明](https://github.com/mksglu/context-mode/releases)
- [怎样比较额度、效率和质量](docs/quickstart.md#怎样判断是否更省更快)

本仓库没有自动安装或接入 context-mode。上下文或 token 减少不等于已证实节省套餐周额度；维护者将通过实际任务试用比较不同配置，再更新经验与建议。
